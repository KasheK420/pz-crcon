## F3 — Sandbox / Server config viewer (read-only v1)

New read-only admin page `/admin/config` with two tabs:

### Tab A: **Server INI** (servertest.ini)
- Read via `docker exec pz-server cat /home/steam/Zomboid/Server/servertest.ini` (or the configured server name).
- Parse line-by-line (`key=value` format).
- Render as a grouped key-value table: General (PublicName, PublicDescription), Capacity (MaxPlayers), Network (PingLimit, DefaultPort), Gameplay (PVP, PauseEmpty, Open, SafetySystem), Whitelist (AutoCreateUserInWhiteList).
- Each row: key, current value, short description (hardcoded hint map from pzwiki), "requires restart" flag.

### Tab B: **Sandbox Vars** (servertest_SandboxVars.lua)
- Read via docker exec.
- Parse the Lua file with a minimal regex-based parser (no full Lua interpreter needed — the file has a predictable `key = value,` structure inside `SandboxVars = { ... }`).
- Render categorised (Population, Weather, Loot, Combat, Vehicles, Skills, etc.) as key-value table.
- Link to full pzwiki docs for the var.

**Edit = Phase 2.** For Phase 1.6, read-only display. Banner says "Editing lands in Phase 2 (v0.2.0)".

## F4 — Whitelist admin page + Steam ID-based whitelist

**Data model:** `Player.isWhitelisted` (Bool) already exists. Add optional `Player.whitelistedSteamId` column? NO — `steamId` is already there; Player.isWhitelisted is enough.

Workflow:
- User hits `/admin/whitelist` → sees table of `Player WHERE isWhitelisted=true` OR Players pre-created with `steamId` set and `isWhitelisted=true`.
- **Add Steam ID form**: input field + Add button. Server action creates a Player row if missing (`name: "Pending (<steamid>)"`, `steamId`, `isWhitelisted: true`), or flips `isWhitelisted=true` on existing row. Records AdminAction audit log.
- **Run `addusertowhitelist` RCON command** ONLY when a username is known (existing player). If the row has only a Steam ID and no real username yet, we skip the RCON call — enforcement happens when they connect (Lua mod in Phase 4) or when admin manually runs the command after they first log in.
- **Remove from whitelist**: sets isWhitelisted=false + runs `removeuserfromwhitelist` if username known.
- Page shows a note: "Actual whitelist enforcement by Steam ID requires the Phase 4 Lua mod. Until then, pre-listed Steam IDs are stored here as a source of truth for admin-side reference. Username-based whitelist (`addusertowhitelist`) works today for users who've joined at least once."

New files:
- `app/(admin)/admin/whitelist/page.tsx`
- `components/whitelist/whitelist-table.tsx`
- `components/whitelist/add-steamid-form.tsx`
- `app/api/whitelist/route.ts` — POST (add), DELETE (remove), GET (list)

Sidebar entry: "Whitelist" (ADMIN+).
