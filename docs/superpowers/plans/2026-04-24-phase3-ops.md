# PZ-CRCON Phase 3 — Ops: Backups, Schedules, Settings

> **For agentic workers:** Use the `superpowers:subagent-driven-development`
> skill. Mark tasks with `- [ ]` / `- [x]`.

**Goal:** Everything a server owner needs the panel to do **unattended** —
backups (manual + scheduled), cron-style restart + event schedules, and a
first-class Settings page that covers Discord notifications, user
management, and API tokens. Ship as **v0.4.0**.

**Architecture:** One background worker (`lib/worker.ts`) spawned by
`server/ws.ts` that owns:

- **Backup engine** — creates tarballs of `pz-data/Saves/<prefix>` (+ optional
  mods snapshot) into `BACKUP_PATH`, rotates per `BACKUP_RETENTION_DAYS`,
  records metadata in the existing `Backup` table.
- **Scheduler** — reads enabled `Schedule` rows, enforces cron triggers,
  dispatches to registered handlers (`RESTART`, `BACKUP`, `BROADCAST`,
  `CUSTOM_RCON`).
- **Discord notifier** — outgoing webhook(s) with per-event toggles, driven
  by the `events:admin` WS publisher and a new `notifyDiscord()` helper.

All three pieces talk through the existing `lib/ws/channels.ts` so admin
panels light up in real time while operations happen.

**Tech Stack:** existing, plus:

- `cron-parser` (tiny, no native deps) — parse cron expressions and compute
  next run.
- `tar` (already transitively available in Node through
  `@prisma/engines`? If not, `tar-stream` — stream-based, no native build).

**Reference:** `docs/superpowers/plans/2026-04-24-gap-analysis.md` §3.

**Repo state at plan start:** branch `phase3-ops` off `main` with Phase 2
merged.

## Chunk 0 — Worker & config

- [ ] `lib/worker.ts`: entry point that starts the scheduler, the retention sweeper, and the notification dispatcher. Idempotent (if the WS server is hot-reloaded it re-registers).
- [ ] `server/ws.ts`: call `installWorker()` alongside `installLogStreamer()`.
- [ ] `lib/env.ts`: add `LOGS_RETENTION_DAYS` (14), `BACKUP_COMPRESSION` ("gzip" | "zstd" — default gzip for portability), `DISCORD_WEBHOOK_URL` (optional). Make `BACKUP_PATH` + `BACKUP_RETENTION_DAYS` **required** now (drop the optional-with-default it has today if any).
- [ ] New `SettingsKv` Prisma model (or JSON singleton in a new `AppSettings` row): `key`, `value Json`, `updatedAt` — used for Discord webhook config, notification rules, theme defaults. Single-row helper `getSetting(key)` / `setSetting(key, value)`.

## Chunk 1 — Backups

**Backup contents:** `Saves/<prefix>`, optional `Workshop/` and `mods/`,
excluded: `Logs/`, `*.tmp`, save lock files. Output filename pattern
`pz-crcon_<prefix>_<iso>.tar.gz`. Record per-file size in `Backup.sizeBytes`.

- [ ] `lib/backups/engine.ts`: `createBackup({ kind, createdById })` streams a tarball to `BACKUP_PATH`. Emits `server:lifecycle` phase `saving` for the duration. Avoids running during an active stop/start (uses the same lifecycle mutex).
- [ ] `lib/backups/retention.ts`: `sweep()` deletes backups whose `createdAt < now - retentionDays`, except it **always** keeps the most recent `PRE_RESTART` and `PRE_MOD_UPDATE` kinds. Runs hourly from the worker.
- [ ] `lib/backups/restore.ts`: `restoreBackup(id)` — *requires a prior stop*; untars into a staged dir `.restore-<iso>`, swaps the current `Saves/<prefix>` to `.trash-<iso>`, renames staged to live. **Triple-confirm** pattern (UI passes `confirmPrefix` + `confirmId` + `{ iKnowThisIsDestructive: true }`).
- [ ] `GET /api/backups` (ADMIN+) — paginated.
- [ ] `POST /api/backups` (ADMIN+, CSRF) — body `{ kind: "MANUAL", notes? }` → enqueue.
- [ ] `GET /api/backups/:id` (ADMIN+) — streams the tarball with `Content-Disposition: attachment`.
- [ ] `DELETE /api/backups/:id` (OWNER, CSRF).
- [ ] `POST /api/backups/:id/restore` (OWNER, CSRF) — triple-confirm.
- [ ] `components/backups/*` — table with download / restore / delete per row, create-dialog with notes field.
- [ ] `/admin/backups/page.tsx` SSR shell.
- [ ] Unit tests: retention keeps pinned kinds; engine tolerates a missing `Saves/` dir with a helpful error; restore rejects when lifecycle phase ≠ `idle` and container is running.
- [ ] Integration tests for each route.

## Chunk 2 — Schedules

**Kind enum (initial):** `RESTART`, `BACKUP`, `BROADCAST`, `CUSTOM_RCON`.
Each schedule has a `payload` JSON field interpreted by its handler.

- [ ] `prisma/schema.prisma`: tighten `Schedule.kind` to a Prisma enum `ScheduleKind`. Add `timezone String @default("UTC")` and `@@index([enabled, nextRunAt])`.
- [ ] `lib/schedules/cron.ts`: thin wrapper around `cron-parser`. Exposes `computeNextRun(expr, { tz, after })`.
- [ ] `lib/schedules/runner.ts`: every 30 s, fetch all enabled schedules whose `nextRunAt <= now`. For each, run handler in sequence, update `lastRunAt` / `nextRunAt`. Never double-fire; uses a short Postgres advisory lock per schedule id.
- [ ] `lib/schedules/handlers/restart.ts`: accepts `{ warningMessages?: string[], warningOffsetsSec?: number[] }`; if set, broadcasts `servermsg` at each offset before triggering `gracefulRestart()` — which already owns the save + stop.
- [ ] `lib/schedules/handlers/backup.ts`: calls `engine.createBackup({ kind: "AUTO" })`.
- [ ] `lib/schedules/handlers/broadcast.ts`: accepts `{ text: string }`; calls `servermsg`.
- [ ] `lib/schedules/handlers/custom-rcon.ts`: accepts `{ command: string }`; validated against the RCON command catalog for role `OWNER` (only the schedule author's level matters, but since schedules are OWNER-only this is fine).
- [ ] `GET /api/schedules` (ADMIN+), `POST` (OWNER, CSRF), `PATCH /api/schedules/:id` (OWNER, CSRF), `DELETE /api/schedules/:id` (OWNER, CSRF).
- [ ] `components/schedules/cron-picker.tsx`: presets (every hour, every 3 h, daily at 04:00, weekly) + expert-mode raw cron text input with live "next run" preview.
- [ ] `/admin/schedules/page.tsx` SSR + client table.
- [ ] Seed a disabled example "Daily restart at 04:00 UTC" on a fresh install.
- [ ] Unit tests: next-run arithmetic, handler dispatch, advisory-lock race (integration test with two runners in parallel).
- [ ] Integration tests for each route.

## Chunk 3 — Settings (Discord + Users)

- [ ] `lib/notifications/rules.ts`: canonical list of event keys (`player.join`, `player.leave`, `player.death`, `player.ban`, `player.kick`, `lifecycle.started`, `lifecycle.stopped`, `lifecycle.restart`, `backup.created`, `backup.failed`, `mod.updated`). Each has a label + default enabled/disabled. Persisted in `SettingsKv`.
- [ ] `lib/notifications/discord.ts`: tiny embed builder + POST; swallows non-2xx, logs + surfaces via `events:admin`.
- [ ] `lib/notifications/dispatcher.ts`: subscribes to `events:admin` (internally), filters by rules, fans out to the webhook. When disabled globally, still receives events — just doesn't send.
- [ ] `POST /api/settings/discord` (OWNER, CSRF) — body `{ webhookUrl?: string, rules: Record<EventKey, boolean>, username?: string, avatarUrl?: string }`. Masks URL on GET for non-OWNER (returns the hash prefix only).
- [ ] `GET /api/settings/discord` (ADMIN+) — masked or revealed based on role.
- [ ] `GET /api/settings/users` (OWNER) — list `User` rows + last-seen + role.
- [ ] `PATCH /api/settings/users/:id` (OWNER, CSRF) — change role (cannot demote self below OWNER if last OWNER).
- [ ] `DELETE /api/settings/users/:id` (OWNER, CSRF) — removes user row; next login would fail unless they're in `DISCORD_ADMIN_IDS`.
- [ ] `components/settings/discord-tab.tsx`: webhook URL field (masked until reveal), per-event toggles grid, "Send test embed" button.
- [ ] `components/settings/users-tab.tsx`: table with role selects + disable button.
- [ ] `/admin/settings/page.tsx` tabs (Discord / Users / Tokens).
- [ ] Unit: rules merge-with-defaults round-trip.
- [ ] Integration: role change invariants (cannot delete last OWNER).

bot lives in a possible **Phase 3.5**.

## Chunk 4 — API tokens

- [ ] `lib/tokens/issue.ts`: `issueToken({ userId, name, scopes, expiresAt? })` — returns `{ id, prefix, secret }` where `secret` is **shown once**; we store `hash = argon2id(secret)` + random 8-char `prefix`.
- [ ] `lib/tokens/verify.ts`: `verifyAuthorizationHeader(req, requiredScope)` → `ApiToken` or `null`. Updates `lastUsedAt` async.
- [ ] Decision: **argon2** pulls a native dep. Use `scrypt` from node:crypto to avoid it. Document in a comment that argon2id would be stronger but scrypt is enough for API tokens that we *also* rate-limit.
- [ ] `POST /api/settings/tokens` (authed, CSRF) — body `{ name, scopes: string[], expiresInDays?: number }`. Response includes the one-time `secret`.
- [ ] `GET /api/settings/tokens` (authed) — lists own tokens; OWNER sees all.
- [ ] `DELETE /api/settings/tokens/:id` (authed) — revoke.
- [ ] `app/api/auth/api-token/route.ts`: generic middleware endpoint reused by Phase 4's webhook ingest and any future REST consumer.
- [ ] Unit tests: hash verification, scope matching, expiry math.

## Acceptance criteria

- [ ] A fresh install on HomePL auto-schedules the 04:00 UTC daily backup **disabled**, and OWNER can enable it via `/admin/schedules` with a working "next run" preview.
- [ ] Manual backup from `/admin/backups` produces a downloadable tarball; retention sweep deletes a backup older than `BACKUP_RETENTION_DAYS`, except `PRE_RESTART` kinds.
- [ ] Restoring a backup is a triple-confirm flow that refuses to run while the PZ container is up.
- [ ] A scheduled restart fires at the configured time, broadcasts in-game warnings at the configured offsets, then invokes `gracefulRestart()`. The lifecycle panel shows all phases.
- [ ] Discord webhook toggles survive a redeploy (stored in `SettingsKv`). Sending a test embed lands in the configured channel.
- [ ] OWNER can create an API token, copy the `secret` once, and use it via `Authorization: Bearer <prefix>.<secret>` to hit a test endpoint. Revoked tokens return 401.
- [ ] Last-OWNER invariant: attempting to demote the only OWNER returns 400.
