# PZ-CRCON Phase 1.7 — Config Editor, Server Controls & Logs Fix

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Wire editable config for `MajorlukPZ.ini` + `MajorlukPZ_SandboxVars.lua`, add server lifecycle controls (start/stop/restart/force-stop/abort), and fix the broken `/admin/logs` viewer — all without SSH.

**Architecture:** Pz-crcon gains two new host integrations: (a) a read-write bind-mount of the `pz-data` volume for direct FS reads/writes of the config files, (b) an isolated `tecnativa/docker-socket-proxy` sidecar with an explicit endpoint allowlist for container start/stop/restart/kill. Config writes are atomic (tmp -> fsync -> rename) with per-file `.bak-<iso>` in a sibling `.backups/` dir, gated by a process-level mutex and a "lifecycle must be idle" check so pz-server's own shutdown-flush cannot race the panel. Lifecycle orchestration uses RCON first, then the Docker proxy, emitting phase transitions over WS.

**Tech Stack:** Node 22 / Next.js 15 / dockerode (TCP for control, unix socket for reads) / async-mutex / rcon-client / shadcn/ui / Zod / Vitest / Prisma 5 / PostgreSQL 16.

**Reference:** Spec at `docs/superpowers/specs/2026-04-20-pz-crcon-config-editor-and-server-controls-design.md`.

**Repo state at plan start:** On branch `phase1.7-config-editor-lifecycle`. Phase 1.6 admin tools merged: read-only config viewer, whitelist, RCON catalog, startup viewer.

## Appendix: Rollback quick-reference

| Thing | How to revert |
|---|---|
| Config write misbehaves | Copy `.backups/<file>.bak-<iso>` over original, then `POST /api/admin/server/restart` |
| docker-socket-proxy wedged | `docker rm -f pz-crcon-socket-proxy` — lifecycle endpoints 503, rest fine |
| Writer bug corrupts a file | Stop pz-crcon, use SSH + editor |
| Volume mount conflict | Revert compose to pre-1.7 (no `/pz-data` mount), recreate pz-crcon |
