## Features (all in one PR)

### F1 — Favicon + social metadata
- Replace default Next.js favicon with an in-game PZ survivor icon.
  - Place SVG at `public/favicon.svg` (hand-craft a minimalist green crosshair + skull OR embed a generic survival icon — keep it original, don't rip copyrighted assets).
  - Fallback PNG at `public/favicon-32x32.png`.
  - `app/icon.png` 512×512 for high-res.
- `app/layout.tsx` metadata: set `title`, `description`, `openGraph.images`, `twitter.card`.
- Result: tab shows icon, shared links show preview.

### F2 — Real Knox County map with live player markers
Replace `RealPzMap` iframe with native Leaflet + tile layer + RCON-driven markers.

- Install: `pnpm add leaflet react-leaflet` + `pnpm add -D @types/leaflet`
- Tile source: `https://pzmap.crash-override.net/tiles/v0_unstable/B41/{z}/{x}/{y}.png` (public community tile server). Document in code comment that we're guests; if the server dies, switch to self-hosted tiles via `pzmap2dzi` (Phase 2).
- Map bounds: Knox County extent is approximately `[0, 0]` to `[10224, 10576]` in world coordinates, mapped to Leaflet `latLngBounds`. Use CRS.Simple.
- New component `components/map/knox-map.tsx` (client component — Leaflet is DOM-only).
- Dynamic-import with `next/dynamic` ssr: false in the public page (Leaflet bundles break SSR).
- Markers: fetch `/api/players/positions` every 10s; each returns `[{name, x, y, region, day}]`. Phase 1.5 data source: since the Lua mod isn't shipped yet, the **endpoint returns only names from RCON `players`** with fake/center coordinates — render them clustered at map center with an "approximate location" note. When Phase 4 Lua mod lands, swap backend to return real positions with no frontend change.
- Overlay panel on map bottom-left: "Live positions require the PZCrcon Lua mod (Phase 4). Until then, player names are listed at a placeholder location."
- Keep the `RealPzMap` iframe component as a fallback route at `/map-legacy` for quick compare.

### F3 — Enhanced Admin Overview status cards
Currently Admin Overview has basic cards. Add:
- **TPS**: RCON doesn't expose TPS. Approximate: tail `docker logs pz-server` and grep `TPS: ([0-9.]+)` — last match within 60s wins. If unavailable show "--".
- **In-game time & day**: PZ logs and RCON emit no clean reader. For Phase 1.5, show **real uptime** (seconds since first RCON connect after process start, not process start itself).
- **Memory + CPU**: new endpoint `GET /api/admin/host-stats` reads `/sys/fs/cgroup/memory.current` and `cpu.stat` inside the pz-crcon container for its own usage, AND `docker stats --no-stream pz-server --format json` (requires mounting `/var/run/docker.sock:/var/run/docker.sock:ro` into pz-crcon and running Docker CLI inside container — **risky privilege escalation**). Simpler: add `dockerode` npm client, connect to `/var/run/docker.sock` socket, call `containers/pz-server/stats?stream=false`. Mount docker.sock read-only.
- **Weather**: RCON has `getoption SnowIsPileUp` and similar scalar reads but not current weather. Skip for Phase 1.5, add `"Weather: see in-game"` placeholder.

Update `components/overview/status-cards.tsx` to render the enhanced grid. New endpoint at `app/api/admin/host-stats/route.ts` (ADMIN+).

### F4 — Live console log streaming
- New WS channel `logs:server` (MODERATOR+ per `lib/ws/channels.ts`).
- Backend log source: read `docker logs -f pz-server` via the dockerode client. Pipe stream into `publish("logs:server", { line, ts })`. Start the tail on first subscriber, stop when last unsubscribes.
- **Handle terminal colours**: PZ logs have ANSI codes. Strip them server-side using `/\x1b\[[0-9;]*m/g` before publishing.
- New admin page `app/(admin)/admin/logs/page.tsx` with a `LogViewer` client component (virtualized list, autoscroll, freeze on click, filter input, export button).
- Add "Logs" item to sidebar nav under ADMIN group, MODERATOR+.

### F5 — Connection instructions on Admin Overview (not just public)
Small addition: put an info card "Server join info" on `/admin` so admins can copy-paste to Discord without switching tabs. Reuses `<JoinInfo />` component.

### F6 — Workshop mod sync job
Rather than relying on the one-off manual SQL seed, ship a CLI script `scripts/sync-mods.ts` that:
- Reads `MOD_WORKSHOP_IDS` from `/opt/docker/projectzomboid/.env` (or takes IDs from CLI args)
- Calls Steam Workshop `GetPublishedFileDetails` API in batches of 100
- Upserts `Mod` rows with `name`, `thumbnailUrl`, and bumps `loadOrder`
- Runs on container start (add to entrypoint) or manually via `docker exec pz-crcon tsx scripts/sync-mods.ts`.

## Implementation order (minimize rebuilds)

1. **Install deps first** (leaflet, react-leaflet, dockerode, @types/leaflet) — one `pnpm install`.
2. Favicon + metadata (F1). No deps, self-contained.
3. Mod sync script (F6). Self-contained.
4. Host-stats endpoint (F3). Stands alone.
5. Log streaming (F4). Uses dockerode.
6. Knox map (F2). Uses leaflet.
7. Admin Overview wiring (F3 + F5). Integrates earlier additions.
8. One PR. One build. One deploy.
